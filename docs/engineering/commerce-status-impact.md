# 商业交易与单一主状态影响审计

## 当前状态事实来源

| 对象 | 现状 | 整改 |
| --- | --- | --- |
| 云服务器、物理机 | `resourceStore` 同时暴露运行状态、健康、到期和生命周期请求状态 | `resource.status` 成为唯一主状态；健康、到期和自动续费保留为辅助事实 |
| 存储 | `storageStore` 同时使用存储状态、挂载状态和容量分级 | `space.status` 成为唯一主状态；容量风险由 `UsageMeter` 表达，挂载关系仅在关系区展示 |
| 订单 | `orderStore` 以申请类型和待处理状态承载购买及运维 | 单一 `CommerceOrder.status` 统一支付与履约阶段，历史变化进入时间线 |
| 账单 | 无独立事实来源 | 新增 `billStore`，账单状态只表达应收、支付、取消和退款 |
| 软件、文件、操作记录 | 各自使用不一致的 submitted、processing、running 等状态 | 统一为等待执行、执行中、已完成、失败、已取消 |

## 当前交易事实来源

- 商品目录与计价：`features/marketplace`、`features/pricing`。
- 购买草稿：`features/purchase/state/purchaseStore.ts`。
- 购买、续费、扩容和免费运维记录：混杂在 `orderStore`、`resourceStore`、`storageStore`。
- 本次迁移后：订单由 `orderStore` 管理，账单由 `billStore` 管理，收银台编排支付与履约；资源 Store 只维护资源事实。

## 需要合并或删除的状态

- 删除资源 `lifecycleRequestState`、物理机 `deliveryStatus` 与 `extensionStatus` 作为并列状态事实。
- 删除订单的申请型状态及页面层 `paymentStatus`、`provisionStatus` 并列展示方式。
- 健康、到期、容量、计费模式、自动续费、挂载数量不再使用主状态徽标。
- 页面不得自行推导状态名称或迁移；统一映射从领域类型导出。

## 需要迁移的文案

- “提交购买申请/提交配置”迁移为“确认订单/创建订单并支付”。
- “续费申请/延期申请/扩容申请”迁移为“续费/续租/扩容”；已下线的资源操作入口不再迁移。
- “申请编号/申请记录”迁移为“订单编号/订单记录”。
- 免费挂载、卸载、网络和释放操作使用“确认操作/正在执行/已完成”，不产生交易记录。

## 受影响页面和 Store

- 商城、云服务器购买、物理机购买、存储购买、收费软件购买。
- 云服务器与物理机列表/详情、存储列表/详情、文件任务、软件安装、网络规则。
- 订单列表/详情、新增账单列表/详情、新增收银台、成功状态、操作记录与全局导航。
- `resourceStore`、`storageStore`、`purchaseStore`、`orderStore`、新增 `billStore`、软件/文件/操作 Store。

## 新订单与账单关系

- 预付费新购、续费、续租、收费扩容和收费软件购买：一个订单至少关联一个价格快照一致的账单。
- 按量订单先开通，账单保留明确账期；不进入预付费收银台。
- 免费运维操作不创建订单或账单。
- 免费挂载、卸载、标签、镜像制作和网络规则直接执行并写入全局操作记录，不生成账单。
- 订单描述交易和履约，账单描述应收与支付；任何页面均不把两者状态并列为对象的多个主状态。

## 旧数据迁移方式

- `orderStore` 与 `storageStore` 提升持久化版本；读取旧版本时只迁移可验证的资源关系，申请型记录不进入新订单集合。
- 新订单和账单使用独立存储键及结构校验；缺失、损坏或旧字段不完整时安全恢复为正式初始数据。
- 迁移不生成已支付事实、第三方交易号、真实基础设施结果或孤立资源引用。
