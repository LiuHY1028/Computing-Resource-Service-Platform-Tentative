# 全项目最终交付执行计划

## 剩余页面与当前缺口

| 模块 | 正式路由 | 当前缺口 |
|---|---|---|
| 存储管理 | `/storage`、`/storage/:storageId` | 列表、详情、挂载关系和操作均未实现 |
| 镜像管理 | `/images` | 分类、详情、导入任务和关联资源未实现 |
| 软件中心 | `/software` | 目录、兼容性、安装任务和资源联动未实现 |
| 网络与访问 | `/network-access` | 统一规则管理和资源详情联动未实现 |
| 订单 | `/orders`、`/orders/:orderId` | 购买申请记录、详情和持久化未实现 |
| 操作记录 | `/operation-records` | 跨模块统一记录未实现 |

剩余路由当前由 `ModulePlaceholderPage` 承载。购买提交尚未生成申请记录，资源详情中的存储、镜像、软件、网络和操作数据仍来自资源领域内嵌快照。正式页面仍存在 URL 调试状态参数；顶部反馈和物理机交付文案存在产品化泄漏。

## 内部阶段、依赖与门槛

1. 存储：先建立版本化本地持久化和统一操作记录基础，再实现存储页面及资源挂载联动。
2. 镜像：复用持久化基础，建立镜像目录，并让云服务器购买和资源关联读取同一数据源。
3. 软件：以资源 Repository 为目标选择来源，统一安装任务与资源详情展示。
4. 网络：复用既有端口/IP 校验，统一网络中心和资源详情规则。
5. 订单与记录：购买提交创建申请快照，统一汇总前述模块操作。
6. 联动与清理：移除占位页、调试参数和开发文案，完成导航、404、返回与刷新路径。
7. 最终验收：更新交付文档和 README，执行完整自动检查及双桌面视口浏览器检查。

每个业务阶段必须通过对应自动化测试、TypeScript 和 Lint 后提交。最终阶段必须通过完整测试、生产构建、`git diff --check`、正式路由浏览器冒烟、控制台和横向溢出检查；浏览器检查不生成或保存页面截图。
