# 数据工作区视觉返工影响

## 必须删除的旧结构

- 存储列表中由 `DataTable` 重复生成的正文标题、说明和主操作区。
- 存储列表的独立大筛选区、表格卡片外框及少量数据时被容器拉出的空白。
- 文件管理器的页面内重复标题、分散的地址栏与命令栏、无选中时仍占位的详情面板。
- 文件管理器中把排序、视图、详情和任务入口分散到多个视觉区域的旧组织。
- 正式页面继续使用的 `storage-table`、旧 `file-manager-*` 布局类和传统 `management-*` 表格外壳。

## 新样板结构

- 存储管理：单一 `PageTitleBar` → 紧凑资源概览带 → 统一数据工作区（Command Toolbar / 条件标签 / Selection Bar / DataTable V2 / 结果与分页）。
- 文件管理：单一 `PageTitleBar` → 一体化 Command Bar（地址、搜索和上下文命令）→ 按需三栏工作区（Navigation / Files / Inspector）→ 浮动任务中心与 Toast。
- 统一三层 Surface、数据工作区 Token、DataTable V2、UsageMeter V2 和 StatusBadge V2。

## 需要迁移的页面

- 云服务器、物理机、镜像管理、网络与访问、订单、操作记录。
- 存储详情和资源详情中的磁盘、挂载、健康、网络、软件、操作记录等子表。
- 其他正式运行页面中的公共 `Table` 数据列表。

## 不需要修改的领域逻辑

- 存储、文件、资源、订单、操作记录及价格 Store 的数据关系和持久化语义。
- 存储购买、挂载、扩容、续期、释放申请的既有领域边界。
- 文件上传、下载、复制、移动、重命名、删除、撤销、任务记录和预览能力。
- Hash 路由、离线单 HTML 交付方式和外部运行时零依赖约束。
