# 待确认问题

> 本文主体只记录尚未获得可靠结论的问题；新关闭的问题保留一行追溯记录。<br>
> “建议的暂定方案”用于原型继续推进，不代表业务规则已经确认；后续获得结论后，应同步更新 `01-requirements-baseline.md` 与 `02-decision-log.md`。

## 1. 确认优先级

| 优先级 | 含义 | 处理规则 |
|---|---|---|
| P0 | 阻塞业务数据模型固化、核心业务页面定稿和正式接口契约 | 不阻塞工程初始化、Design Token、基础主题、应用框架和公共组件；业务原型只能使用本文明确记录的可替换临时假设 |
| P1 | 不确认会影响核心页面字段、操作可用性或关键接口 | 高保真页面定稿前确认 |
| P2 | 可用明确标注的临时假设推进 | 演示前确认或接受暂定方案 |

建议确认角色说明：

- **产品负责人**：确认范围、业务规则、流程和字段口径；
- **基础设施/后端负责人**：确认资源能力、接口、状态和底层约束；
- **安全/运维负责人**：确认网络访问、凭证及危险操作约束；
- **设计负责人**：确认文案、交互呈现和设计规范冲突；
- **业务/财务负责人**：仅在产品确实需要计费或账单时确认费用口径。

P0 是业务固化闸门，不是基础工程启动闸门。阶段 1–4 可以在 P0 问题关闭前推进，但不得借此固化任何待确认的业务对象、字段、状态或接口语义。

## 7. 推荐确认顺序

1. **产品负责人先确认 OQ-001、OQ-002、OQ-010、OQ-011、OQ-014、OQ-015**：先锁定主体、订单边界、售卖、资源状态和操作系统规则；OQ-013 已关闭。
2. **产品与基础设施共同确认 OQ-012、OQ-017、OQ-020、OQ-023、OQ-024、OQ-041、OQ-042、OQ-043**：再锁定购买配置和存储/站点模型。
3. **网络、安全、镜像、软件和监控负责人确认 OQ-025–OQ-029、OQ-044–OQ-046**：形成可实现的字段与接口。
4. **设计评审确认 OQ-050–OQ-058**：临时假设不阻塞结构文档，但需在领导演示前统一话术。

## 8. 在问题关闭前的实施纪律

- P0 问题会阻塞业务数据模型固化、核心业务页面定稿和正式接口契约，但不阻塞工程初始化、Design Token、基础主题、应用框架和公共组件。
- P0 问题关闭前，业务原型只能使用对应 `OQ-*` 中明确记录的可替换临时假设；临时假设不得成为正式业务状态、后端校验、价格规则、审批规则或权限规则。
- 所有临时示例数据必须标注为示例，不得被产品文档引用为真实库存、价格、容量上限或状态口径。
- “一键安装、自动安装、预装软件”均不得作为已确认能力；当前只确认“从软件中心选择并安装”的能力方向。
- “不按需”不得自动解释为包月、包年、买断、内部配额或免费。
- “独占”不得自动解释为某种租户、项目或 IAM 方案。
- “系统盘底层可能对应 K8S 配额”不得自动落实为某一存储实现。
- 物理机 OS/镜像规则未确认前，不能把云服务器购买字段机械复制到物理机。
- 复杂 VDC/VPC 是否排除仍是暂定范围边界；当前只实现证据明确的端口和来源 IP 能力。
