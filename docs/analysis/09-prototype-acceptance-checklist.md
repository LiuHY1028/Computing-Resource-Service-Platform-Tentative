# 原型验收清单

> 用途：后续高保真交互原型的逐项验收基线。本清单不替代业务确认；凡标记为待确认的规则，应验证“未被固化”，而不是验证某个未经确认的结论。

## Task 15：状态与交易验收增补

- [ ] 云服务器、物理机、存储、订单、账单和任务在同一信息层级各只有一个主状态；列表与详情使用同一映射。
- [ ] 健康、到期风险、容量使用、计费模式和自动续费只作为辅助信息，不与主状态并列。
- [ ] 新购、续费、续租、收费扩容、收费变配和收费软件购买统一创建订单；预付费同步创建账单。
- [ ] 免费挂载、卸载和网络规则不创建订单或账单，但写入操作记录。
- [ ] 待支付订单可进入收银台并取消；支付后订单、账单、资源/期限/容量与操作记录一致。
- [ ] `ORD-01/02`、`BILL-01/02`、`CHK-01` 使用正式交易语言，不出现申请型购买文案。
- [ ] `STO-03` 由产品卡、规格卡、容量滑块与快捷项、Stepper、周期卡、条件挂载和 Sticky 实时报价组成；无旧大数字区块、重复标题或报价内滚动。
- [ ] 1366×768、1440×900、1920×1080 无整页横向滚动、裁切、控制台 warning/error。
- [ ] `verify:status`、`verify:commerce` 和原有五个领域验证器全部通过。
- [ ] 离线单 HTML 重新生成并通过 `verify:offline`。

## 使用说明

- 验收前先阅读[需求基线](./01-requirements-baseline.md)、[待确认问题](./03-open-questions.md)、[页面清单](./05-page-inventory.md)、[用户流程](./06-user-flows.md)和[UI规范提取](./07-ui-spec-extraction.md)。
- `P0` 为领导演示和核心评审必须通过项；`P1` 为完整产品方案必须通过项。
- 若待确认项使用临时方案推进，页面、数据和文档中必须统一标注“暂定”，并能在规则确认后集中替换。
- 当前需求基线阶段没有前端工程，因此 TypeScript、Lint、Build 和浏览器运行项记为“不适用”；工程初始化后转为强制项。

## 业务完整性

- [ ] `P0` 产品被表达为独立的算力资源服务产品，而不是 AI 开发平台的附属商城。
- [ ] `P0` 商城仅售卖云服务器和物理机两类计算资源。
- [ ] `P0` 商城与购买后的资源管理在信息架构和页面职责上清晰分离。
- [ ] `P0` 云服务器和物理机均有购买、已购列表及资源详情的完整入口。
- [ ] `P0` 已购资源体现“购买者独占”，且没有擅自增加资源共享、转授权或审批规则。
- [ ] `P0` 包周期与按量流程、价格、周期、续费、退款和支付只使用 DEC-046 已确认的统一交易边界。
- [ ] `P0` 云服务器配置中内存与系统盘是两个不同字段。
- [ ] `P0` 系统盘显示暂定默认值 `30 GB`，没有写成 `30 GB 内存`。
- [ ] `P0` 界面能区分系统盘、本地数据存储和高性能共享存储。
- [ ] `P0` 用户文案默认不暴露 K8S、Pod、HostPath、NFS 等底层术语；必要的技术映射只出现在说明文档或开发注释。
- [ ] `P0` 独立存储空间可在资源流程中选择或挂载，且未被错误地与服务器捆绑售卖。
- [ ] `P0` 站点/分区在商城、购买或资源信息中有清晰体现。
- [ ] `P0` 云服务器创建包含镜像选择；物理机流程不把镜像选择写成已确认规则。
- [ ] `P0` 资源管理覆盖开机、关机、监控和连接信息；操作合法状态矩阵未被擅自固化。
- [ ] `P1` 网络能力覆盖端口暴露、端口转发和允许访问 IP。
- [ ] `P1` 软件中心支持选择软件或环境并发起安装，未擅自确认预装、一键、版本、卸载等规则。
- [ ] `P1` 订单、账单和操作记录可分别查看，订单与账单不混为一个对象。
- [ ] `P1` AI 开发平台的 Notebook、训练、推理、Token、模型商品没有进入当前产品范围。

## 交互完整性

- [ ] 所有按钮点击后都有可观察反馈：加载、结果、页面变化、弹窗关闭或明确禁用原因。
- [ ] 所有提交操作在请求处理中阻止重复提交。
- [ ] 开机、关机、端口开放、挂载、安装等影响资源的操作有确认或清晰后果说明。
- [ ] 操作成功后相关列表、详情、订单或操作记录中的数据同步更新。
- [ ] 操作失败显示可理解原因，并在适用时提供重试或返回入口。
- [ ] 取消、关闭、返回不会无提示丢失已填写内容；确需丢弃时有确认。
- [ ] 搜索、筛选、标签页和分页均能改变结果或明确显示无匹配结果。
- [ ] 复制 IP、端口或 SSH 信息后有成功反馈。
- [ ] 禁用操作能通过 Tooltip 或附近说明解释前置条件，不能仅以灰色按钮代替说明。
- [ ] 购买成功后的暂定落点统一为相应资源详情，且提供查看订单入口。

## 页面与组件状态

- [ ] 每个列表页覆盖首次加载、正常有数据、空数据、筛选无结果、加载失败和重试。
- [ ] 每个详情页覆盖加载、正常、数据获取失败和关联对象缺失。
- [ ] 每个表单覆盖默认、Hover、Focus、已填写、校验错误、错误聚焦、Disabled 和提交中。
- [ ] 每个异步业务动作覆盖未开始、处理中、成功和失败反馈；这些是交互状态，不被解释为正式业务状态机。
- [ ] 空状态提供与当前任务相关的下一步入口；没有权限或规则依据时不展示虚构的权限文案。
- [ ] 错误状态不泄露底层 K8S、Pod 或内部接口细节。
- [ ] Loading 状态避免布局大幅跳动，并保持当前上下文可识别。

## UI 规范符合度

- [ ] 使用统一 Design Token，不在业务页面散落重复色值、圆角、阴影和间距常量。
- [ ] 主色、成功、警告、错误及中性色遵循[UI规范提取](./07-ui-spec-extraction.md)中的页码和冲突处理规则。
- [ ] 顶部导航高度、侧栏展开/收起宽度、主内容外间距和标题栏高度符合 PDF p.4-p.7。
- [ ] 1080p 基准下使用 24 栏、20 px 边距和 20 px 栏距；非基准宽度通过响应式布局适配，不复制设计画板的绝对坐标。
- [ ] 按钮、输入框、选择器、弹窗、标签页、Tooltip、表格、分页和表单复用公共组件。
- [ ] 页面不使用截图代替真实文本、控件或数据展示。
- [ ] 页面主体不依赖大量绝对定位；绝对定位仅用于 Tooltip、浮层等合理场景。
- [ ] 阴影只用于规范允许的悬停、下拉和悬浮层场景。
- [ ] OneAiNexus 名称和 Logo 仅作为规范来源，不被硬编码成产品正式品牌。
- [ ] 规范外组件在[页面组件映射](./08-page-component-mapping.md)中有依据、状态和复用范围。

## 指定流程验收

- [ ] `FLOW-CLOUD-BUY`：能完成云服务器选择、配置、确认和成功反馈，并按资源可访问性进入 `RES-02` 或 `ORD-02`。
- [ ] `FLOW-PHYSICAL-BUY`：能完成物理机选择、配置、确认和交付结果展示，并显式保留 OS/自动开机待确认项。
- [ ] `FLOW-RESOURCE-MANAGE`：能从列表进入详情，查看监控和连接信息并发起资源操作。
- [ ] `FLOW-STORAGE-MOUNT`：能创建存储空间、区分两类数据存储，并从资源上下文发起挂载。
- [ ] `FLOW-NETWORK-OPEN`：能配置端口、转发关系和允许 IP，并处理失败。
- [ ] `FLOW-SOFTWARE-INSTALL`：能选择软件和目标资源，显示安装处理与结果。
- [ ] `FLOW-ORDER-VIEW`：能从订单列表进入订单详情和关联资源。
- [ ] `FLOW-FAILURE`：所有关键动作均有加载、失败原因、重试或安全返回。
- [ ] `FLOW-DEMO`：领导演示路径无需临时跳转、刷新或口头补充才能走完。
