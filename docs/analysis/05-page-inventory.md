# 页面清单

> 文档状态：需求基线（实施前）
>
> 产品工作名：算力资源服务平台（非正式名称）
> 本清单覆盖完整产品原型，不只覆盖商城。页面字段和动作中的“暂定/待确认”不得在实现时升级为正式业务规则。

## 1. 清单约定

### 1.1 页面与视图

- 稳定页面 ID 限定为：`MKT-01`、`BUY-01`、`BUY-02`、`RES-01`～`RES-04`、`STO-01`、`STO-02`、`IMG-01`、`SW-01`、`NET-01`、`ORD-01`、`ORD-02`、`OPS-01`。
- `RES-01` 与 `RES-03` 是“我的资源”同一页面外壳下的两个标签视图，但分别保留稳定 ID，便于后续任务、流程和验收引用。
- 创建存储、上传镜像、安装软件、开放端口等使用弹窗或抽屉，不虚增页面 ID。
- 监控嵌入 `RES-02`/`RES-04` 资源详情，不创建独立一级监控页面。

### 1.2 角色口径

当前只确认一种产品使用者：**技术型资源使用者**。会议认为用户能理解服务器、GPU、代码和网络等概念（会议 00:15:17–00:15:31，L713–721）。评审者和领导是原型演示受众，不是权限角色；管理员、审批人、财务角色、租户管理员均未确认。

### 1.3 字段标记

| 标记 | 含义 |
|---|---|
| `[确认]` | 材料明确支持，可进入需求基线 |
| `[修正]` | 会后补充覆盖旧理解 |
| `[暂定]` | 为保证原型连贯而采用，可替换 |
| `[待确认]` | 不得作为后端校验、状态枚举或权限规则实现 |

### 1.4 优先级

| 优先级 | 含义 |
|---|---|
| P0 | 核心购买、交付、管理或领导演示主路径所必需 |
| P1 | 完整产品必需，但可在核心链路跑通后实现 |
| P2 | 可增强完整性，当前清单没有把纯增强页独立出来 |

优先级只表示后续原型实施顺序，不代表商业优先级或业务承诺。

1. `BUY-01` 中“系统盘 30 GB”必须与内存规格分区展示；不得写成“30 GB 内存”或移除系统盘。（会后补充 L5–14）
2. 数据存储用户文案暂用“本地数据存储/高性能共享存储”；HostPath/NFS 仅作为内部映射，是否直接外露待确认。（会后补充 L16–29）
3. `MKT-01` 不把“无卡”写成已确认筛选项。会议中该建议被明确否定或改为不设该筛选（会议 00:02:33–00:02:47，L95–121）。
4. `BUY-02` 不复用 `BUY-01` 的镜像选择组件作为默认规则；物理机是否选择操作系统须等待确认。（会议 00:14:25–00:14:47，L677–691）
5. `RES-02/04` 的状态标签和操作可用性必须由统一数据源驱动；在状态机未确认前，原型只展示样例反馈，不建立业务判断规则。
6. `ORD-01/02` 不展示价格、余额、支付、账期、续费、退款和审批字段；会议仅明确存在购买记录方向，计费细则未拍板。
7. 任何按钮都必须有反馈；提交中禁用重复提交，失败保留用户输入并允许重试。
8. 页面没有数据时应说明原因并提供下一步，而不是仅显示空白表格。
