# 资源商城视觉竞品研究与改版方案

> 研究日期：2026-07-22
>
> 对应基线：Task 05A 已提交版本 `f4ed8ea`
>
> 研究范围：仅诊断当前 `/marketplace`、研究公开官网并提出视觉方案；不调整业务需求、数据字段、筛选规则或购买流程。

## 1. 研究方法与边界

- 在本地开发服务器中分别打开 `/marketplace?type=cloud` 与 `/marketplace?type=physical`，以 1920×1080、1366×768 两种视口进行截图和 DOM 尺寸测量。
- 卡片“额外留白比例”按 `渲染高度 - 内边距 - 标题/摘要/规格实际内容 - 操作区 - 既定间距` 估算。它表示由同排等高拉伸产生的额外空间，不是对白色像素面积的图像识别结果。
- 竞品研究仅访问公开官网，不登录账号，不复制品牌文案、价格、Logo、插图、前端代码或视觉资产。
- 竞品只用于抽象信息层级、卡片密度、分类识别、视觉节奏和操作路径；本项目仍以现有 UI 规范、Design Token、AppShell 和公共组件为准。
- 本轮没有把任何外部截图保存到项目或提交到 Git。本地页面诊断截图仅临时保存在系统临时目录。

## 2. 当前页面问题

### 2.1 实测尺寸与首屏密度

| 视口与类型 | 筛选区高度 | 卡片宽度 × 行高 | 卡片实际内容高度 | 等高额外留白 | 首屏完整卡片 | 首屏第二排 |
|---|---:|---:|---:|---:|---:|---:|
| 1920×1080 云服务器 | 216 px | 524.7 × 354 px | CPU 约 297 px；GPU 约 352 px | CPU 57 px / 16.1%；GPU 2 px / 0.6% | 3 张 | 仅露出约 34 px |
| 1920×1080 物理机 | 224 px | 524.7 × 373 px | CPU 约 297 px；GPU 约 371 px | CPU 76 px / 20.4%；GPU 2 px / 0.5% | 3 张 | 仅露出约 7 px |
| 1366×768 云服务器 | 216 px | 340 × 354 px（第二排可达 382 px） | 首排 CPU 约 297 px；GPU 约 352 px | 首排 CPU 16.1%；第二排可配置卡约 7.9% | 0 张 | 首排仅露出约 40 px |
| 1366×768 物理机 | 224 px | 340 × 420 px（首排） | CPU 约 335 px；GPU 约 390–418 px | CPU 85 px / 20.2%；GPU 2–30 px / 0.5%–7.1% | 0 张 | 首排仅露出约 32 px |

补充测量：

- 1920 视口的有效商品区约 1614 px，当前采用 3 列；按现有 20 px 列间距计算，改为 4 列时单卡仍约 388.5 px，足以容纳紧凑的 2×2 核心指标。
- 1366 视口的商品区约 1060 px，当前 3 列时单卡 340 px，内容可读且没有横向溢出。若强行改为 4 列，单卡只约 250 px，长 CPU 型号、整机摘要和不可配置原因会明显增加换行，因此 3 列更合适。
- 页面说明在 1920 下高 110 px，在 1366 下因换行增至 166 px；再叠加 216–224 px 筛选区、类型页签、结果标题与多段垂直间距，1366 的商品卡起点已落到 y=728–736 px。
- CPU 卡规格区通常为 3 个字段，GPU 卡为 5 个字段。两者被放入同一等高行后，稀疏 CPU 卡被高信息量 GPU 卡或换行后的不可配置操作区拉高。
- 当前 CTA 按钮本体约 82×32 px，并非尺寸过大；问题主要是操作区独占整行、上方边界和 `margin-top: auto` 共同放大了“底部空仓”的感受。不可配置说明换行后，操作区高度可由约 49 px 增至 77 px，并进一步拉高整行。
- 两个视口均未发现横向溢出，说明问题是垂直密度和层级，而不是基础响应式失效。

## 4. 可复用设计模式

### 4.1 紧凑卡片信息架构

采用固定的五段结构：

1. 类型与状态；
2. 规格名称；
3. 核心硬件指标；
4. 站点、系统盘或整机摘要等次要说明；
5. 操作区。

段落顺序固定，但高度由真实内容决定。信息槽位一致比统一 `min-height` 更重要。

### 4.2 硬件参数层级

- 规格名称是卡片标题，不与标签争夺权重。
- CPU、内存、GPU/加速卡、GPU 数量构成 2×2 指标区；CPU 计算卡可用 CPU、内存、系统盘、站点填满同一矩阵，不显示虚假 GPU。
- 指标标签使用次级文字，指标值使用较高字重与更紧凑行高。
- 默认系统盘继续明确表达为存储容量；物理机只展示已确认的整机字段。

### 4.3 卡片色彩策略

- 以白色/中性表面为主体，高饱和彩色面积控制在卡片的小局部，而不是整卡填色。
- 使用现有主色浅背景承载类型标识；现有品牌蓝—蓝绿渐变只用于 2–3 px 顶部识别条、小图标底或局部边框。
- 成功色只表达“可配置”；不可配置继续使用语义状态样式和文字原因。普通资源分类不借用警告色。
- 不增加新的全局颜色，也不在业务 CSS 中写原始色值。

### 4.4 分类标识策略

- 第一眼应同时识别“云服务器/物理机”和“CPU/GPU”。
- 资源类型用小面积浅色底、局部识别条或几何硬件符号表达；计算类型保留文字标签，避免只依赖颜色。
- GPU 型号继续是数据字段，不把“无卡”或缺省值做成型号选项。

### 4.5 Hover 与 Focus 策略

- Hover 只强化边框、使用现有轻量阴影，并可上移 1 px；不使用大阴影、光晕或明显漂浮。
- Focus 必须至少与 Hover 同等可见，整卡可感知但主要操作仍是公共 Button。
- 禁用卡不产生可点击暗示，禁用原因继续可见并可由 Tooltip 补充。

### 4.6 CTA 布局

- 每卡保留一个“立即配置”，仍由资源自身状态控制可用性。
- 操作区底部对齐，但通过一致内容槽位和紧凑间距实现，不以大块弹性空白实现。
- 按钮无需扩大；应减少按钮上下的独占空间，并让禁用原因紧贴操作区。

### 4.7 筛选栏压缩策略

- 搜索、站点、计算类型、GPU 条件和可配置状态尽量按 24 栅格同排或紧凑两排。
- 当前筛选回显与结果数量保持独立层级，但空回显不预留可见大块高度。
- 目标高度约 144–160 px，比当前 216–224 px 降低约 26%–36%。
- 1366 下允许控件换成两排，但不引入新的移动端断点体系，也不改变筛选规则。

### 4.8 等高卡片处理

- 同一行允许操作区对齐，但取消无必要固定高度/过大 `min-height`。
- 通过标题最多两行、次要说明最多两行、禁用原因紧凑两行等“内容上限”控制差异；完整内容用 Tooltip 提供。
- CPU 与 GPU 卡可共享五段结构，而不强迫规格区拥有相同字段数。
- 目标将稀疏卡的等高额外留白从当前 16%–20% 降到 5%–8% 以内。

### 4.9 首屏信息密度

- 1920×1080：目标为完整显示筛选区、4 张完整首排卡片，并露出第二排的一部分。
- 1366×768：维持 3 列。通过压缩页面说明与筛选区，优先让首排商品在首屏中形成有效比较。
- 对物理机而言，340 px 宽度下保留 5 个字段、长整机摘要和禁用原因时，若同时要求“完整首排 + 第二排露出”，需要把卡片压到约 230 px 或将筛选默认收起，容易导致内容截断或改变交互呈现。基于当前实测，更稳妥的阶段目标是云服务器首排尽量完整、物理机首排显示 70%–90%，而“完整首排 + 第二排露出”优先保证在 1920 视口。若 1366 也必须严格达到，需在实施前确认是否接受可折叠筛选摘要。

## 5. 三套改版方向

### 5.1 方案 A：紧凑专业型

| 维度 | 方案 |
|---|---|
| 页面栅格 | 1920 使用 4 列、每卡 6/24 栏；1366 使用 3 列、每卡 8/24 栏 |
| 卡片结构 | 五段式结构；16 px 内边距；8–12 px 段落节奏；2×2 核心指标；内容驱动高度 |
| 色彩策略 | 白色主体 + 主色浅背景标签 + 细主色识别条；功能色仅用于真实状态 |
| 信息层级 | 类型/状态 → 名称 → 核心指标 → 次要说明 → CTA |
| 目标高度 | 云服务器约 250–280 px；物理机约 270–300 px |
| 首屏数量 | 1920 完整 4 张并露出第二排；1366 保留 3 列，通过压缩上部区域显著增加首排可见度 |
| 优点 | 密度改善最大、视觉风险最低、最容易保持现有公共组件和 UI 规范的一致性 |
| 风险 | 如果只压缩尺寸而不调整层级，仍可能显得“整齐但普通”；色彩改善有限 |
| 与 UI 规范关系 | 完全沿用 24 栅格、8 px 圆角、现有间距与语义色；不新增 Token |
| 改造工作量 | 中低；主要是业务组件布局和页面局部样式调整 |

### 5.2 方案 B：高级彩色型

| 维度 | 方案 |
|---|---|
| 页面栅格 | 同样优先 1920 四列、1366 三列；保留足够宽度承载局部视觉标识 |
| 卡片结构 | 五段式基础上增加 40–56 px 高的轻量类型识别区，或采用 2–3 px 渐变顶边 + 小型硬件符号底 |
| 色彩策略 | 主色浅背景区分资源类型；品牌蓝—蓝绿渐变只用于局部；单卡高饱和彩色面积控制在约 5%–8% |
| 信息层级 | 资源类型与计算类型更鲜明；标题和核心指标仍主导，装饰不压过数据 |
| 目标高度 | 云服务器约 260–290 px；物理机约 280–310 px |
| 首屏数量 | 1920 完整 4 张并露出第二排；1366 三列，首排可见度优于当前但略低于方案 A |
| 优点 | 资源类型识别更快，能在不营销化的前提下提升节奏和高级感 |
| 风险 | 渐变或标签使用过量会接近科技宣传页；类别色与成功/不可配置语义可能混淆；对对比度和 Focus 校验要求更高 |
| 与 UI 规范关系 | 只使用现有品牌色、品牌渐变、主色浅背景和语义色；遵循“渐变局部使用”的既有规范 |
| 改造工作量 | 中高；需要精确打磨类型标识、Hover/Focus、长文本和不同状态组合 |

### 5.3 方案 C：高密度规格型

| 维度 | 方案 |
|---|---|
| 页面栅格 | 由多列卡片转为全宽规格行或分组列表；固定列展示名称、站点、CPU、内存、GPU、系统盘/摘要、状态与 CTA |
| 卡片结构 | 每行约 56–72 px；标题为首列锚点，硬件值列对齐，次要信息放第二行或 Tooltip |
| 色彩策略 | 极低彩色面积；类型分组头或首列使用浅色识别，状态保持语义色 |
| 信息层级 | 以列对齐和横向比较为最高优先级，接近云规格表 |
| 首屏数量 | 在压缩筛选后，理论上可连续看到约 6–10 条规格，扫描效率最高 |
| 优点 | 参数比较效率最高，规格数量增长时扩展性好，等高问题基本消失 |
| 风险 | 商城的“发现感”下降；物理机长摘要在 1366 下难以容纳；逐项 CTA 较拥挤；可能需要更强的表格/响应式行为 |
| 与 UI 规范关系 | 可复用现有 Grid、Button、Tooltip 与表格视觉原则，但与当前商品卡业务组件差异最大 |
| 改造工作量 | 高；需要重构结果呈现与窄屏列策略，测试范围最大 |

## 6. 推荐方案

### 6.1 推荐方向

推荐采用 **方案 A 的卡片密度与结构 + 方案 B 的局部色彩和高级感**，不采用方案 B 的独立大识别区，也暂不切换到方案 C 的纯规格表。

具体组合：

- 1920 由 3 列改为 4 列，单卡约从 524.7 px 收窄到 388.5 px；1366 保持 3 列、单卡 340 px。
- 卡片改为五段式，核心参数采用 2×2 指标布局；站点、系统盘或整机摘要进入次级区域。
- 云服务器目标高度约 250–280 px，物理机约 270–300 px；不设置超过真实内容需要的固定高度。
- 使用 2–3 px 局部品牌渐变识别条、主色浅背景类型标签或小型硬件符号底；单卡高饱和面积不超过约 5%–8%。
- Hover 只强化边框、使用现有轻量阴影并上移 1 px；Focus 明确可见；禁用卡不产生可点击暗示。
- 筛选区目标压缩到约 144–160 px，空筛选回显不占用大块可见高度。

### 6.2 推荐原因

1. 当前最严重的问题是栅格和等高留白，方案 A 可以直接解决 1920 的低密度与 CPU 卡的 16%–20% 额外空白。
2. 仅做尺寸压缩不足以解决“呆板”和类型识别弱，方案 B 的小面积品牌色能提供必要节奏，又不会把页面变成促销页。
3. RunPod、Lambda 和 DigitalOcean 共同证明硬件比较依赖稳定的指标顺序；Hetzner 证明类型/状态应先行；Vercel 证明细边框、局部色彩和短文本可以在高密度下保持清晰。
4. 该组合不改变商品字段、筛选逻辑、购买入口或公共组件 API，实施风险明显低于纯表格重构。

### 6.3 预期改善

| 指标 | 当前 | 推荐方案目标 |
|---|---|---|
| 1920 列数 | 3 列 | 4 列 |
| 1920 单卡宽度 | 524.7 px | 约 388.5 px，降低约 26% |
| 云服务器卡高 | 354 px | 约 250–280 px，降低约 21%–29% |
| 物理机卡高 | 373 px（1920） | 约 270–300 px，降低约 20%–28% |
| 稀疏卡额外留白 | 约 16%–20% | 目标控制在 5%–8% 以内 |
| 筛选区高度 | 216–224 px | 约 144–160 px，降低约 26%–36% |
| 1920 首排完整卡片 | 3 张 | 4 张 |
| 分类识别 | 主要依赖文字标签 | 文字标签 + 小面积局部色彩，不只依赖颜色 |

### 6.4 风险与实施前验证点

- 388.5 px 与 340 px 卡宽下，长 CPU 型号、整机摘要和不可配置原因需要真实数据逐项验证；次要说明可以限两行并用 Tooltip 展示完整内容，核心硬件值不可被截断。
- 类型色不能替代状态色。成功色只表达“可配置”，不可配置必须继续有文字原因；普通 CPU/GPU 分类不能使用警告色。
- 1366 的严格“完整首排 + 第二排露出”与当前物理机字段量存在客观冲突。若验收要求两类资源都必须达到，需要先确认是否接受可折叠筛选摘要；否则不应通过隐藏字段或制造新断点来达成。
- 四列卡片需要检查 Select Portal、长标签、键盘 Focus、禁用原因和两种购买入口；视觉优化不能改变现有交互和 URL 状态。
- 新视觉仍应复用公共 Container、Grid、Tabs、Input/SearchInput、Select、MultiSelect、FilterTag、Button 与 Tooltip，不建立新的通用组件体系。
